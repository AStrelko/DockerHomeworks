# THE SECRET SOCIETY — закритий клуб

## Опис проєкту

Я створив навчальний React-застосунок для учасників закритого клубу. Користувач вводить ім’я, отримує профіль, розгадує загадки, заробляє бали, відкриває рівні доступу та досягнення. Рейтинг порівнює учасників, зареєстрованих у цьому браузері. Після розв’язання першої загадки відкривається другий рівень матеріалів, після всіх загадок — третій.

Це демонстраційна локальна реєстрація: профілі зберігаються в `localStorage` і не мають паролів чи серверної авторизації. Дані різних браузерів не синхронізуються.

## Практична робота

Перший етап — повністю робочий сайт клубу та образ `task-manager:1.0`. Назва образу взята з формулювання практичного завдання; назва застосунку всередині образу — THE SECRET SOCIETY.

- `src/App.tsx` — форма вступу, навігація, профіль, перевірка загадок, досягнення та рейтинг.
- `src/data.ts` — дані загадок, правила нарахування балів і рівнів, збереження профілів.
- `src/style.css` — адаптивне оформлення.
- `Dockerfile` — складання й запуск застосунку в контейнері.
- `.dockerignore` — виключення локальних залежностей, збірки, Git, `.env` і тимчасових логів npm.

У Dockerfile використано `FROM`, `WORKDIR`, `COPY`, `RUN`, `ENV`, `EXPOSE`, `CMD`; додатково — `USER`, `ARG`, `LABEL`, `HEALTHCHECK`. Спочатку копіюються `package.json` і `package-lock.json`, після чого виконується `npm ci`; решта коду копіюється окремо. Тому зміна компонента не має повторно встановлювати залежності, а зміна файлів пакета примушує виконати `npm ci` заново. `USER node` запускає застосунок без прав root; перевірка здоров’я звертається до локального HTTP-сервера.

`ARG APP_VERSION` передається під час збірки. Його значення використовується в мітці образу й переноситься до `ENV APP_VERSION`. `ENV APP_MODE=training` доступна всередині запущеного контейнера. Саме значення `ARG` доступне лише під час збірки, якщо його окремо не перенести в `ENV` або `LABEL`.

## Доповнення для домашньої роботи

Після перевірки версії 1.0 я додав у версії 2.0 пошук учасника в рейтингу за ім’ям і стан порожнього результату. Файли для цієї зміни лежать в окремій папці `../version-2-files/`; вони замінюють відповідні файли першої версії перед наступною збіркою. Версія пакета також змінюється з `1.0.0` на `2.0.0`. Образ `task-manager:1.0` залишається старим знімком, а `task-manager:2.0` містить новий компонент.

Порівнювати образи можна за ID, версією в `LABEL`, розміром і поведінкою інтерфейсу. Теги дають можливість повернути попередню робочу версію, зіставляти релізи та розгортати конкретну версію без неоднозначності.

Перевірка збірки застосунку: `npm ci` і `npm run build` для кожної версії. Перевірка Docker: збірка, `docker image inspect`, запуск контейнера, браузер, `docker logs`, `docker ps`, `docker exec`, зупинка та видалення. Кроки експерименту з кешем і `.dockerignore` наведені окремо в особистій інструкції поза директорією застосунку.
