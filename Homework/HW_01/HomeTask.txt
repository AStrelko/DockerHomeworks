Проєктування середовища для розробки програмного продукту

Сценарій: ви приєдналися до команди, яка розробляє платформу онлайн-бронювання готелів. Команда хоче використовувати Docker, щоб спростити розробку та розгортання системи.

Платформа містить такі компоненти:

· сервіс авторизації користувачів;

· каталог готелів;

· сервіс бронювання;

· сервіс оплати;

· база даних;

· сервіс сповіщень.

Необхідно виконати:

1. Аналіз архітектури

Визначити, які компоненти системи можуть бути окремими мікросервісами. Пояснити відповідальність кожного з них.

2. Аналіз контейнеризації

Пояснити, чому для кожного сервісу може бути доцільно використовувати окремий контейнер.

3. Порівняння

Описати, які проблеми можуть виникнути, якщо всі компоненти встановлювати безпосередньо на одному комп'ютері без контейнеризації.

4. Аналіз компонентів Docker

Для кожного з наведених понять описати його роль у майбутньому проєкті:

· Docker Daemon;

· Docker CLI;

· Dockerfile;

· Docker Image;

· Docker Container;

· Docker Registry.



5. Віртуалізація та контейнеризація

Пояснити, чому компанія може обрати контейнери замість створення окремої віртуальної машини для кожного компонента.

6. Практична перевірка

Зробити скриншоти:

· встановленого WSL2;

· Ubuntu у WSL2;

· запущеного Docker Desktop;

· успішного виконання docker run hello-world.

Що потрібно здати

· документ із відповідями на завдання;

· схему архітектури майбутньої системи;

· скриншоти виконаної практичної частини.
