Домашнє завдання. Docker Image Optimization Challenge

Сценарій: ви працюєте в команді розробників, яка готує вебзастосунок до передачі іншій команді. Ваше завдання — підготувати його до розповсюдження через Docker Hub так, щоб інші розробники могли швидко завантажити та запустити застосунок.

Завдання 1. Розробка нового проєкту

Створити окремий React + TypeScript + Vite застосунок на одну з тем:

· MISSION CONTROL — центр управління космічними місіями;

· NEO CITY — система управління містом майбутнього;

· ESCAPE ONLINE — платформа інтерактивних квестів;

· DROPZONE — платформа ексклюзивних товарних релізів;

· DIGITAL MUSEUM — інтерактивний цифровий музей.

Вимоги:

· щонайменше 4 функціональні можливості;

· щонайменше 3 окремі сторінки;

· маршрутизація між сторінками;

· форми для введення даних;

· пошук або фільтрація;

· збереження частини даних у localStorage.

Завдання 2. Створення двох варіантів Dockerfile

Підготувати:

· Dockerfile із базовою конфігурацією;

· Dockerfile з оптимізованою конфігурацією.

У другому варіанті обов'язково використати:

· Multi-stage build;

· оптимізоване кешування;

· .dockerignore;

· відповідний базовий образ;

· окреме середовище для фінального запуску.

Порівняти результати.

Завдання 3. Додаткова оптимізація

Дослідити та застосувати щонайменше дві можливості оптимізації, які не розглядалися в основному Dockerfile.

Наприклад:

· BuildKit cache mounts;

· npm ci замість npm install;

· мінімізація залежностей;

· оптимізація контексту складання;

· використання конкретних версій базових образів.

Пояснити, яку проблему вирішує кожна оптимізація.

Завдання 4. Публікація та версіонування

1. Створити власний репозиторій у Docker Hub.

2. Опублікувати першу версію застосунку з тегом 1.0.

3. Внести зміни до функціоналу або дизайну.

4. Опублікувати другу версію з тегом 2.0.

5. Перевірити наявність обох версій у Docker Hub.

6. Перевірити можливість завантаження кожної версії через docker pull.

Завдання 5. Перевірка незалежності від локального середовища

Уявіть, що ваш комп'ютер не має вихідного коду проєкту.

1. Видалити локальну копію вихідного коду або працювати в окремій чистій директорії.

2. Видалити локальні образи проєкту.

3. Завантажити образ із Docker Hub.

4. Запустити його.

5. Перевірити роботу всіх основних сторінок і функцій застосунку.

Не потрібно видаляти сам проєкт із репозиторію Git або здавати його без вихідного коду — йдеться лише про перевірку запуску опублікованого образу без локальної збірки.

Завдання 6. Документація

Створити README.md, у якому описати:

· призначення застосунку;

· використані технології;

· структуру Dockerfile;

· принцип роботи Multi-stage build;

· результати порівняння розмірів;

· посилання на Docker Hub;

· команди завантаження та запуску;

· доступні версії образу.

Що потрібно здати

1. Посилання на GitHub-репозиторій із React-проєктом.

2. Dockerfile та .dockerignore.

3. Посилання на Docker Hub.

4. Дві опубліковані версії образу.

5. README.md.

6. Скріншоти порівняння розмірів образів.

7. Скріншоти успішного запуску після docker pull.
